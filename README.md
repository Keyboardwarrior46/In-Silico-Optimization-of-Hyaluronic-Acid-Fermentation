## Project Overview
This repository contains a computational simulation modeling the batch and fed-batch fermentation kinetics of *Bacillus subtilis* for the production of high-molecular-weight hyaluronic acid (HA). 

In industrial bioprocessing, the accumulation of extracellular HA creates a profound rheological challenge. The fermentation broth exhibits severe pseudoplastic (non-Newtonian) behavior, causing an exponential rise in apparent viscosity. This viscosity spike directly attenuates the volumetric oxygen mass transfer coefficient ($k_L a$), leading to oxygen starvation and premature batch failure. 

This project mathematically models this fluid constraint and implements an *in-silico* fed-batch substrate feeding strategy to optimize product yield while maintaining manageable rheology for continuous oxygen transfer.

## Core Mathematical Framework
The Python simulation solves a system of stiff ordinary differential equations (ODEs) based on the following principles:
* **Microbial Growth:** Monod kinetics modeling specific growth rate bounded by substrate concentration.
* **Product Formation:** Luedeking-Piret modeling for growth and non-growth associated HA secretion.
* **Rheology:** Ostwald-de Waele power-law modeling translating product accumulation into apparent viscosity (cP).

## Repository Structure
* `bioprocess_simulation.py` - The core Python script utilizing `scipy.integrate.odeint` to solve the kinetic ODEs.
* `HA_fermentation_data.csv` - The exported dataset containing the time-series kinetic and viscosity data generated by the simulation.
* `paper.tex` - The LaTeX source code used to typeset the findings.
* `Lakshya_Agrawal_Bioprocess_Research.pdf` - The final compiled scientific paper, complete with dynamically plotted data visualizations and theoretical downstream processing (DSP) methodologies.

## Running the Simulation
The simulation is self-contained and designed for easy parameter testing. All initial kinetic variables and substrate concentrations are hardcoded directly within the script—no external inputs or complex data pipelines are required to run the baseline model.
